# Project HP API Replicator - Instructions and Memory

## Project Goal

To build a robust Python API using FastAPI to receive and log arbitrary JSON data from remote devices. The API will be secured with JWT authentication, and a command-line interface (CLI) will be provided for managing users and generating JWT tokens. The primary purpose is to capture incoming data in a structured log file for later analysis, as the exact data structure is initially unknown.

## Technology Stack

*   **API Framework:** FastAPI
*   **ASGI Server:** Uvicorn
*   **JWT Handling:** `python-jose`
*   **Password Hashing:** `passlib[bcrypt]` (using `CryptContext`)
*   **CLI Framework:** `Click`
*   **Language:** Python 3.x

## Architectural Decisions

*   **API Framework Choice:** FastAPI was chosen for its modern features, high performance, automatic documentation (OpenAPI/Swagger UI), and robust type hints, which simplify development and maintenance.
*   **Authentication Strategy:** JWT (JSON Web Tokens) was selected for stateless authentication, suitable for API-to-API communication. Tokens are generated by the CLI and validated by the API.
*   **User Management:** A simple CLI `cli.py` is used for prototype purposes to create and delete users. User credentials (hashed passwords) are stored in `users.json`. This is explicitly a prototype solution and would need to be replaced with a proper database and user management system in a production environment.
*   **Data Logging:** Incoming data is written directly to `logs/replication.log` as JSONL (JSON Lines). This allows for easy appending of new data and simplifies parsing each log entry independently. No log rotation is implemented as per user request for this initial version.
*   **Configuration:** A `config.py` module centralizes settings such as `SECRET_KEY`, `ALGORITHM`, and `ACCESS_TOKEN_EXPIRE_MINUTES`.

## Data Flow

1.  **Client (Device):** Sends a POST request to `/data` with a JSON payload and a valid JWT token in the `Authorization` header.
2.  **FastAPI Application (`main.py`):**
    *   Receives the request.
    *   FastAPI's dependency injection (`Depends(get_current_user)`) triggers JWT validation.
    *   If the JWT is valid, the request proceeds.
    *   Extracts the JSON payload.
    *   Records timestamp, source IP, and authenticated user.
    *   Constructs a log entry.
    *   Appends the log entry as a new JSON line to `logs/replication.log`.
3.  **Log File (`logs/replication.log`):** Stores all incoming data for later analysis.

## Security Notes for Production

*   **JWT `SECRET_KEY`:** Must be a strong, randomly generated string and loaded from an environment variable (e.g., `os.getenv("SECRET_KEY")`) rather than hardcoded. Never expose this key.
*   **User Database:** Replace `users.json` with a secure, scalable database for user storage and management.
*   **HTTPS/TLS:** Deploy the API with HTTPS/TLS encryption to protect data in transit.
*   **Rate Limiting:** Implement rate limiting to prevent abuse and denial-of-service attacks.
*   **Input Validation:** While the current API logs arbitrary JSON, for specific known data structures, implement stricter input validation.

## CLI Notes

*   The `create-user` command displays the generated JWT token directly to the console. In a production scenario, consider more secure token distribution methods.
*   The `users.json` file, which stores hashed passwords, should be strictly protected and ideally reside outside of the web server's accessible directories. It is already included in `.gitignore` by default (if a `.gitignore` exists and is properly configured).
